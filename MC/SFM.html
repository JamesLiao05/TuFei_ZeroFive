💡 例如填 16，则机器A、B、C 每次都会各自精准接收 16 个物品。

🎯 为什么我的物品没有平均分配？

SFM 的 OUTPUT TO "A", "B" 默认是瀑布流（优先填充）。它会拼命把 A 塞满，A 满了才溢出给 B。

解决办法：在“传输构建”面板勾选 “严格平均分配”，或者手动拆分成多条 INPUT/OUTPUT 语句。

📦 拆分手写均分示例

如果不使用 IDE，手写均分代码的正确姿势如下：

-- 将原矿均分给 3 台粉碎机，每台 16 个
INPUT 16 #forge:ores FROM "原矿箱"
OUTPUT TO "粉碎机A"

INPUT 16 #forge:ores FROM "原矿箱"
OUTPUT TO "粉碎机B"

INPUT 16 #forge:ores FROM "原矿箱"
OUTPUT TO "粉碎机C"

⚡ 能量 (FE) 需要均分吗？

不需要！ 能量传输没有“堆叠”概念，机器缺多少就会抽多少。直接写 OUTPUT TO "A", "B", "C" 即可，SFM 会自动按需分配能量。

💧 流体 (mb) 怎么均分？

流体和物品一样，默认是优先填充。如果要多台机器均分流体，建议勾选“严格平均分配”，或者使用 Mekanism 的机械管道（自带均分功能）。

🔧 物理管道均分替代方案

如果目标机器超过 5 台，写 SFM 代码会很长。建议：

1. SFM 只负责把物品抽到机器上方的 缓冲箱。

2. 使用 Pipez (分配升级) 或 Mekanism (物流分拣器-轮询模式) 进行物理均分。

FACE 面指定

解决机器多面口冲突。常见：热力顶出底进、Mekanism 侧面输入。

INPUT FROM "机器" FACE BOTTOM
OUTPUT TO "机器" FACE TOP

RETAIN 保留模式

来源容器至少保留指定数量，不被抽走。适用于保持机器最低原料。

INPUT 32 * RETAIN 16 FROM "缓冲箱"

1.21.1 数据组件

替代旧版 NBT 语法，直接跟在物品 ID 后面。

INPUT "minecraft:diamond_pickaxe" {damage:0} FROM "工具箱"
